# Kelishim — правила для Muse Code

## Цель
Собрать мобильный-first веб-прототип реестра обещаний по аренде: источники → извлечение условий → сравнение → вопросы хозяину → ответ → итог сделки.

## Стек по умолчанию
- Frontend: React + Vite + TypeScript + Tailwind CSS.
- Backend: Python + FastAPI.
- Persistence: SQLite или JSON-файл на сделку.
- Tests: pytest для доменного ядра и Vitest/Testing Library для UI.
- Язык интерфейса: русский; кыргызский — только как бонус.

## Неподвижные продуктовые ограничения
- Не определять мошенников, риск, право собственности или юридическую действительность договора.
- Не скрейпить сайты объявлений.
- Не отправлять сообщения хозяину автоматически.
- Каждое извлечённое значение хранить с точной цитатой из исходника.
- Если условие не упомянуто, возвращать `value: null`, не додумывать.
- Решение о совпадении/конфликте принимает код, не модель.
- Сбой модели должен приводить к ручному вводу, а не к белому экрану.
- Нельзя менять схему данных без отдельного решения владельца проекта.

## Порядок разработки
1. Сначала зафиксировать контракт данных и доменные тесты.
2. Затем реализовать нормализацию и статусы.
3. Затем подключать реальные вызовы Muse и только после этого строить UI вокруг состояний загрузки/ошибки/успеха.
4. После каждого модуля запускать тесты и проверять мобильный сценарий.
5. Не добавлять бонусы (кыргызский, PDF, акт имущества), пока не работает hero flow.

## Definition of done
Работает без регистрации по публичной ссылке; demo-пример проходит полный цикл; видны все четыре статуса и цитаты; сообщение нельзя считать готовым без ручного подтверждения; интерфейс содержит постоянную пометку: «Приложение помогает зафиксировать условия и показывает, что нужно уточнить. Это не юридическая консультация».

## Работа Muse Code
Для крупных задач используй планирование, отдельные worktree для параллельных изменений и обязательный reviewer-проход. Не объявляй задачу завершённой только из-за exit code: запускай тесты и smoke-flow сам.
