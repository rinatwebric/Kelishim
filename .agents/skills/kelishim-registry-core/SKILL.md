# Kelishim registry core

## Правила

- Доменное решение не зависит от LLM и UI.
- `value = null` означает «не упомянуто».
- Каждое ненулевое значение должно иметь `quote`, найденную в `raw_text`.
- `confidence < 0.6` или `hedged = true` устанавливает `needs_manual_check = true`.
- Суммы нормализовать с валютой: `30 тыс`, `30 000`, `30к` → `30000`; сом и USD не смешивать.
- Сроки приводить к месяцам, животных — к `yes`, `no`, `negotiable`, `unknown`.

## Статусы

- `unknown`: нет значения ни в одном источнике.
- `single`: значение есть только в одном источнике, либо оно hedged.
- `match`: минимум два значения после нормализации совпали.
- `conflict`: минимум два значения после нормализации различаются.

В UI показывать одновременно символ и слово: `❓ Не указано`, `🟡 Один источник`, `✅ Совпадает`, `⚠️ Противоречие`.

## Обязательные тесты

Покрыть pytest-кейсами суммы, пробелы и `к/тыс`; валюты; сроки; pets; отсутствие значения; hedged; конфликт «30 000 сом» vs «500 USD»; совпадение разных написаний; отсутствие цитаты; owner_reply, меняющий статус.

Не использовать эвристику модели для присвоения статуса. Если вход повреждён, вернуть структурированную ошибку и сохранить исходник для ручного исправления.
