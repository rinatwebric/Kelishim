# Kelishim Muse integration

1. Сначала сверить актуальную документацию хакатона и фактический API-контракт: имена моделей, лимиты аудио/изображений, формат image input и structured JSON. Не выдумывать endpoint или schema.
2. Вынести модели за адаптеры: `transcribe(audio)`, `ocr(image)`, `extract(source_text)`, `draft_questions(registry)`, `draft_owner_message(questions)`, `translate_kg(text)`.
3. Для `extract` использовать единую JSON-схему из 10 условий. На каждый term вернуть `value`, `currency`, `quote`, `confidence`, `hedged`; отсутствующее значение — `null`.
4. После ответа модели провалидировать JSON, диапазон confidence и наличие quote в исходном тексте. При ошибке повторить максимум один раз с тем же исходником и более жёстким указанием схемы.
5. На каждый вызов поставить timeout 30 секунд. После финальной ошибки показать человеку понятный текст и дать ручной ввод; не подставлять фиктивный успешный результат.
6. Не отправлять модели персональные данные сверх нужного исходника и не хранить секреты в frontend. Публичное demo должно использовать обезличенные данные.
7. Реестр пересчитывать кодом после каждого нового source, включая `owner_reply`. Модель не должна решать `match/conflict`.
8. В UI показывать прогресс по источникам и источник ошибки. Для demo допускается сохранённый результат только с явной меткой «сохранённый результат».
9. Кыргызскую версию считать бонусом: если перевод неуверенный, оставить русскую версию и не блокировать hero flow.
