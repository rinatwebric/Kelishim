# Kelishim QA and demo

## Smoke flow

Пройти без регистрации: старт → «Попробовать на примере» → источники → видимый анализ → реестр → открыть цитату → вопросы только по `conflict/unknown` → отредактировать сообщение → вручную подтвердить → добавить owner reply → пересчитать → итог сделки.

## Проверить

- 360—430 px без горизонтальной прокрутки; touch targets минимум 44 px.
- У каждого действия есть loading, empty, error и success state; нет сырых stack trace.
- Значения имеют точные цитаты; низкая уверенность и hedged заметны текстом, не только цветом.
- Все статусы имеют иконку и слово; контраст минимум AA.
- Сообщение нельзя считать готовым до явного подтверждения; приложение ничего не отправляет.
- Перезагрузка страницы сохраняет сделку; предусмотрено удаление данных.
- API timeout/retry приводит к ручному вводу.
- Внизу постоянно видна юридическая оговорка из AGENTS.md.

## Acceptance evidence

Собрать таблицу по 3—5 обезличенным образцам: сколько условий в эталоне, сколько извлечено верно, пропущено и ошибочно. Записать известные ошибки честно. Проверить, что README описывает запуск, архитектуру, ограничения, реальные/сохранённые demo-данные и команды тестов.

## Demo timing

0:00—0:20 проблема; 0:20—1:30 источники и реестр; 1:30—2:15 конфликт залога; 2:15—2:45 вопрос и ответ хозяина; 2:45—3:00 локальная ценность Бишкека и честные ограничения.
